Publicación en GitHub Pages (frontend)

Cuenta: argos4all · correo de la cuenta: argos4all@gmail.com · sitio resultante: https://argos4all.github.io/<repositorio>/

Indicaciones paso a paso (primera publicación)

  1. Crea el repositorio: entra a github.com/new con tu cuenta argos4all. Nombre sugerido: escuela-ia. Visibilidad: Público. Pulsa Create repository.
  2. Sube el archivo: dentro del repositorio pulsa Add file → Upload files, arrastra el archivo index.html (esta aplicación) y pulsa Commit changes.
  3. Activa GitHub Pages: en Settings → Pages, en "Build and deployment" elige Source: Deploy from a branch, Branch: main y carpeta / (root). Pulsa Save.
  4. Espera 1 a 2 minutos y abre https://argos4all.github.io/escuela-ia/ (si usaste otro nombre de repositorio, ajusta la dirección). Cada vez que actualices index.html en la rama main, el sitio se actualiza solo.

Publicación automática desde esta página (opcional)

  1. Crea un token en github.com/settings/personal-access-tokens/new (Fine-grained). En Repository access elige Only select repositories y selecciona tu repositorio. En Permissions → Repository permissions → Contents marca Read and write. Genera y copia el token (empieza con github_pat_…).
  2. Pega el token en el campo Token (PAT) de arriba. Se guarda únicamente en este navegador; nunca se incluye en el código publicado.
  3. Pulsa Publicar index.html: la aplicación crea o actualiza index.html en tu repositorio mediante la API de GitHub, y GitHub Pages publica la versión nueva automáticamente en 1 a 2 minutos.

Por seguridad, esta aplicación nunca guarda ni usa tu contraseña de GitHub: desde 2021 GitHub solo permite automatización con tokens (PAT). Si usas una computadora compartida, pulsa "Borrar token" al terminar.

Notas de funcionamiento y seguridad

  • Back4App · subida de archivos: si el servidor responde error 130 ("File upload by public is disabled"), la aplicación crea automáticamente un usuario de sesión en tu app de Back4App y reintenta la subida; no necesitas hacer nada. Alternativa manual: en back4app.com → tu app → App Settings → Security & Privacy, activa la subida pública de archivos.
  • Back4App · almacenamiento: al eliminar un documento de la lista, el registro se borra, pero el archivo puede permanecer en el almacenamiento de Back4App (su eliminación definitiva requiere la Master Key). Límpialos desde el dashboard si lo necesitas.
  • Back4App · usuario de prueba: durante la validación se creó el usuario edudocs_prueba_tmp en tu app. Puedes eliminarlo desde el dashboard (Users) o dejarlo; no se usa.
  • Gemini: la clave viaja en el código público de GitHub Pages. Recomendación: en Google AI Studio, restringe la clave por sitio web (https://argos4all.github.io) y rotala si sospechas fuga; luego actualízala aquí sin tocar el código.
  • Gemini: si ves "User location is not supported", la red desde la que se abre la página bloquea la API de Google; abre el sitio desde tu navegador habitual (otra red). Si ves "API key not valid", corrige la clave en Configuración.
  • Acceso admin: la contraseña se verifica localmente con hash SHA-256; nunca se envía a ningún servidor. Tras 5 intentos fallidos, el acceso se bloquea 60 segundos.
  • Privacidad: los documentos y el historial del chat se guardan en Back4App y en este navegador. La aplicación no usa analítica ni rastreo.
